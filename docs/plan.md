# 開発計画：ImeCenterView

## 目的

IME のオン／オフ切り替え時に、画面中央へ四角い領域と「あ」／「A」を一瞬表示する常駐アプリを作る。
昔の Microsoft IME にあった画面中央表示機能と同じ使用感を目指す。

## スコープ

### 対象とするもの（v1.0）

- IME オン／オフの検知と、画面中央への「あ」／「A」の表示
- フェードアウト表示、フォーカスを奪わない・クリック透過
- マルチモニター・高 DPI 対応
- タスクトレイ常駐、終了メニュー、スタートアップ登録
- 表示時間・サイズ・不透明度の設定

### 対象外とするもの（将来検討）

- カタカナ・全角英数・半角カナなど、入力モードの詳細表示（`IMC_GETCONVERSIONMODE` を使えば拡張可能）
- IME 以外のキーボードレイアウト切り替え表示
- 管理者権限ウィンドウへの対応（アプリ自体を管理者実行すれば動く可能性はあるが、v1.0 では保証しない）

## フェーズ 1：IME 状態の取得

- [x] `Native/NativeMethods.cs` に必要な P/Invoke を定義
  - `GetForegroundWindow`, `GetWindowThreadProcessId`, `GetGUIThreadInfo`
  - `ImmGetDefaultIMEWnd`, `SendMessageTimeout`
- [x] `ImeState`（`On` / `Off` / `Unknown`）を定義
- [x] `IImeStateReader` と `ImeStateReader` を実装（フォーカスウィンドウ優先 → IME ウィンドウ取得 → `IMC_GETOPENSTATUS`）
  - `ImmGetContext` は使わない（解放漏れの原因になるため）
  - 取得処理の中でヒープ確保を行わない（`GUITHREADINFO` などは構造体で扱う）
- [x] 確認用に、状態をデバッグ出力（`Debug.WriteLine`）する仮のタイマーを置く

**完了条件**：以下のアプリで IME を切り替えたとき、デバッグ出力の On/Off が正しく変わる

- メモ帳
- ブラウザ（Edge / Chrome）
- VS Code
- Office（Word / Excel）
- エクスプローラーのファイル名変更

また、ポーリングを 30 分動かしたままにしても、ハンドル数・GDI・USER オブジェクト数が増え続けない

## フェーズ 2：変化検知

- [x] `IForegroundWindowProvider` を定義し、実装を用意
- [x] `ImeMonitor` を実装
  - `DispatcherTimer` で 100ms ごとにポーリング
  - フォアグラウンドウィンドウが変わったときは状態を記録するだけ
  - 同じウィンドウで On ⇔ Off が変わったときだけ `ImeStateChanged` イベントを発行
  - `Unknown` が絡む変化ではイベントを発行しない
  - `IDisposable` を実装し、`Dispose` でタイマー停止とイベント解除を行う
- [x] `ImeMonitorTests` でユニットテストを書く
  - 同じウィンドウで Off → On：イベントあり
  - 同じウィンドウで状態変化なし：イベントなし
  - ウィンドウが変わり、同時に状態も変わる：イベントなし
  - Unknown → On、On → Unknown：イベントなし

**完了条件**：テストがすべて通り、実機でも IME 切り替え時だけデバッグ出力にイベントが出る（Alt+Tab だけでは出ない）

## フェーズ 3：オーバーレイ表示

- [x] `OverlayWindow` を作成
  - 正方形 162×162（DIP）、角丸なし、グレー `#2F2F2F`・約 85% の背景、グレー（`#DEDEDE`）の文字。以前の Microsoft IME の表示を実測して合わせる
  - `SourceInitialized` で `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW` を付与
- [x] `Show(ImeState state)` を実装：文字を「あ」／「A」に切り替え、プライマリモニター全体の中央に表示（マルチモニター対応はフェーズ 4）
- [x] 700ms 表示 → 300ms でフェードアウト → 非表示
- [x] 表示中に再度呼ばれたら、文字を差し替えてタイマー・アニメーションをリセット
- [x] ウィンドウ・アニメーション・タイマー・ブラシは 1 インスタンスを使い回す（`Completed` などのイベント登録は初期化時の 1 回だけ）
- [x] Debug ビルド専用のストレステスト機能を追加：オーバーレイ表示（あ／A の交互）を 1 万回連続で実行し、実行前後のハンドル数・GDI・USER オブジェクト数・メモリを比較してログに出す
- [x] `ImeMonitor.ImeStateChanged` と接続する

**完了条件**

- IME を切り替えると画面中央に「あ」／「A」が表示され、自然に消える
- 表示中も入力中のアプリで文字入力を続けられる（フォーカスが奪われない）
- 表示中にその位置をクリックしても、下のウィンドウに届く
- タスクバーや Alt+Tab に表示されない
- 連打しても表示が乱れない
- ストレステストの前後で、ハンドル数・GDI・USER オブジェクト数がほぼ変わらない（GC 後のメモリも増え続けない）

## フェーズ 4：マルチモニター・DPI 対応

## フェーズ 5：常駐機能

- [x] 名前付き `Mutex` で二重起動を防止
- [x] `TrayIcon` を実装（`NotifyIcon`）
  - メニュー：「一時停止／再開」「設定」「スタートアップに登録」（チェック式）「終了」。「設定」はフェーズ 6 で設定ウィンドウを作るまで無効（グレー表示）にしておく
- [x] 「終了」でトレイアイコンを破棄してからアプリを終了
- [x] 終了処理を `App.OnExit` に集約：タイマー停止 → イベント解除（`SystemEvents` 含む）→ トレイアイコン・アイコン・メニュー破棄 → Mutex 解放
- [x] アイコンは埋め込みリソースの `.ico` から読み込み、`Bitmap.GetHicon` は使わない
- [x] スタートアップ登録（`HKCU\...\Run` への書き込み／削除）
- [x] Debug ビルド専用のストレステストに、一時停止／再開を 100 回繰り返して前後のリソース使用量を比較する機能を追加（`--stress-pause`）

**完了条件**：トレイから一時停止・終了ができ、スタートアップ登録後にサインインし直すと自動起動する。終了後にトレイにアイコンが残らない。一時停止／再開を 100 回繰り返してもハンドル数が増えない

## リソースリーク検証

昔の IME の切り替え表示で起きていた「ハンドルやメモリを確保したまま解放しない」不具合を再発させないため、以下を各フェーズの完了時とリリース前に実施する。

### 監視する数値

| 項目 | 取得方法 |
|---|---|
| ハンドル数 | `Process.HandleCount`／タスクマネージャー「詳細」タブの「ハンドル」列 |
| GDI オブジェクト数 | `GetGuiResources(GR_GDIOBJECTS)`／タスクマネージャーの「GDI オブジェクト」列 |
| USER オブジェクト数 | `GetGuiResources(GR_USEROBJECTS)`／タスクマネージャーの「USER オブジェクト」列 |
| プライベートメモリ | `Process.PrivateMemorySize64`／タスクマネージャーの「メモリ（アクティブなプライベートワーキングセット）」列 |

タスクマネージャーでは「詳細」タブの列見出しを右クリック →「列の選択」で上記の列を追加できる。より詳しく見る場合は Process Explorer も使う。

### 検証手順

1. **ストレステスト**（Debug ビルド）：オーバーレイ表示を 1 万回実行し、前後の数値を比較する。起動直後の初期化分を除き、増加がないこと
2. **長時間テスト**：通常利用しながら 8 時間以上常駐させ、`ResourceMonitor` のログで数値が右肩上がりになっていないことを確認する
3. **状況変化テスト**：スリープ復帰、画面ロック／解除、モニターの抜き差し、DPI 変更をそれぞれ繰り返し、数値が増えないことを確認する

### 判定基準

- ハンドル数・GDI・USER オブジェクト数：初期化後はほぼ一定（一時的な増減はよいが、傾向として増え続けない）
- メモリ：GC によって上下するが、下限値が増え続けない

## リスクと対策

| リスク | 対策 |
|---|---|
| 一部アプリで IME 状態が取れない | `Unknown` として表示しない。取れないアプリを README に記載 |
| `SendMessage` が応答しないアプリで固まる | `SendMessageTimeout` + `SMTO_ABORTIFHUNG` を使う |
| オーバーレイがフォーカスを奪う | `WS_EX_NOACTIVATE` と `ShowActivated=False`、`SWP_NOACTIVATE` を徹底 |
| 他の最前面ウィンドウの下に隠れる | 表示のたびに `HWND_TOPMOST` で Z オーダーを再設定 |
| ハンドル・メモリのリーク（昔の IME で発生していた問題） | CLAUDE.md の「リソース管理」ルールの徹底、診断ログ、ストレステスト・長時間テストの実施 |
| 切り替え直後に取得すると古い値が返る | ポーリング方式なので次の周期で拾える。必要ならポーリング間隔を調整 |
